# Agent Watcher

A macOS menu bar app that shows the usage limits of the AI harnesses installed
on the machine: **Claude Code**, **Codex** and **Cursor**.

Inspired by the `belizario.agents` Omarchy plugin (dotfiles), rebuilt natively
in Swift/SwiftUI.

- **Left click** the icon: a panel with each harness, its plan, how much of
  each window is left (5h session, weekly, per-model limits) and when it
  resets.
- **Right click**: Refresh / Settings… / Check for Updates… / About / Quit.
- The icon is a **270° horseshoe** with a sparkle in the middle; the arc fills
  with the tightest account-level window across all harnesses. Model-scoped
  allowances (Fable) and Cursor's Auto/API pools do not color it; Cursor uses
  the combined **Overall** usage. When any harness has **20% or less**
  left, the icon leaves the system color and turns **orange**, getting redder
  as it nears **10%**. At **10% or less** the sparkle in the middle becomes a
  bang. Both thresholds are configurable.

## Install

Requires macOS 14+ and Xcode / Command Line Tools (Swift 6).

```bash
make install   # builds build/AgentWatcher.app, copies it to ~/Applications and opens it
```

To start it at login, turn on "Launch at login" in Settings.

Other targets: `make run` (builds and opens the local .app), `make test`,
`make clean`.

### App icon

The icon is generated by `scripts/app_icon.py` into `Resources/AppIcon.icns`.
To change the palette or background (needs `rsvg-convert`, from `librsvg`):

```bash
make icon PALETTE=aurora BG=light && make run
# palettes:    ocean (default), aurora, lilac, amber, ice
# backgrounds: black (default), dark, graphite, light, color
```

## Releases

Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`, one job per stage,
each handing its output to the next as an artifact:

| Stage | Does | Artifact |
|---|---|---|
| `build` | tests, universal (Apple silicon + Intel) build | `app-unsigned` |
| `sign-app` | Developer ID signature, hardened runtime | `app-signed` |
| `dmg` | installer DMG (no credentials in this job) | `dmg-unsigned` |
| `sign-dmg` | Developer ID signature on the DMG | `dmg-signed` |
| `notarize` | notarization, stapling, Gatekeeper check | `AgentWatcher-dmg` |
| `publish` | GitHub Release with the DMG and its SHA-256 | |

```bash
git tag v0.1.0 && git push origin v0.1.0
```

**Resuming after a failure:**

- *Re-run failed jobs* on the run page redoes only the failed stage and the
  ones after it; earlier stages keep their artifacts (kept 14 days).
- After changing the workflow or a script, start a new run on the same tag,
  taking the earlier stages from the failed run (both runs must be on the same
  commit):

  ```bash
  gh workflow run release.yml --ref v0.1.0 -f resume_run=<run id> -f start_at=notarize
  ```

Running the workflow by hand on a branch produces the signed DMG as an artifact
without publishing (`-f notarize=false` skips notarization).

The workflow reads these Secrets: `MACOS_P12_BASE64`, `MACOS_P12_PASSWORD`,
`MACOS_NOTARY_APPLE_ID`, `MACOS_NOTARY_PASSWORD` (and optionally
`MACOS_TEAM_ID`, `MACOS_CODESIGN_IDENTITY`). Send them from a `.env` without
printing values:

```bash
scripts/setup-github-secrets.py            # dry run: lists what would be sent
scripts/setup-github-secrets.py --apply    # reads ./.env, or ../bgdesk/.env
```

The same pipeline runs locally with `make release`, reading `./.env` (see
`.env.example`); `SKIP_NOTARIZE=1 make release` only signs. Stages also run on
their own, working on the files in `build/`:

```bash
scripts/release.sh build sign-app   # just these
scripts/release.sh notarize         # resume: notarize the signed DMG in build/
```

## Updates

The app checks `GET https://api.github.com/repos/belizariogr/agentwatcher/releases/latest`
20 s after launch and then every 6 hours (prereleases and drafts are ignored).
When the release's tag is newer than `CFBundleShortVersionString`, it:

1. downloads the `AgentWatcher-*.dmg` asset and checks it against `SHA256SUMS.txt`;
2. mounts it and copies the app next to the installed one;
3. refuses it unless it is intact, has the bundle id `com.belizariogr.agentwatcher`
   and a Developer ID signature from team `3Z7C3Q7NMT`;
4. swaps the bundle in place, quits and reopens.

The install waits while the panel is open. Local builds (`make install`, ad-hoc
signed) only show that a release exists and never replace themselves; a copy in
a folder the user can't write to (or run from the DMG) links to the release page.
Settings › Updates turns checking and automatic install on or off; the right-click
menu has **Check for Updates…** and **About Agent Watcher**.

```bash
defaults write com.belizariogr.agentwatcher checkForUpdates -bool false
defaults write com.belizariogr.agentwatcher installUpdatesAutomatically -bool false
```

## Where the numbers come from

| Harness | Limits | Credentials |
|---|---|---|
| Claude Code | `GET https://api.anthropic.com/api/oauth/usage` | The CLI's OAuth token in the Keychain (`Claude Code-credentials`), or `$CLAUDE_CONFIG_DIR/.credentials.json` |
| Codex | JSON-RPC `account/rateLimits/read` on `codex app-server` | The CLI itself (`~/.codex/auth.json`, or `$CODEX_HOME`) |
| Cursor | `POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage` (+ `GetPlanInfo`) | The Cursor CLI token in the Keychain (`cursor-access-token`), or the editor's login (`state.vscdb`) |

No token leaves the machine except in the header of the requests to Anthropic
and Cursor. The app does not renew tokens: if Claude's expires, opening Claude
Code renews it; for Cursor, run `cursor-agent login`.

Cursor's included usage is monthly and split into two pools: **Cursor Models**
(Auto + Composer) and **Other Models** (third-party models picked by name). The
icon uses **Overall**, the combined share of both, not the tighter pool; that
figure is not drawn as a third bar. Claude's
model-scoped windows (Fable) show in the panel but do not color the icon. Codex
shows only the main account allowance (session/weekly, or monthly credit on
Enterprise); Spark and other model buckets are ignored. The Claude usage request
identifies as Claude Code (User-Agent from `claude --version`) so Anthropic
does not park it in the aggressive rate-limit bucket.

If a refresh fails, the panel keeps the last known numbers. A rate limit
(Anthropic limits the usage endpoint readily) is routine and shown silently;
other failures (e.g. the network) add a warning and how old the numbers are. Every
check is saved to `~/Library/Application Support/AgentWatcher/usage.json`, so
the last known numbers survive a relaunch too. A missing, expired or rejected
login is different: the old numbers are dropped and the harness shows that it
needs a login.

## Settings

The **Settings** button (⌘,) at the bottom of the panel opens a window with:

- refresh interval (1 min to 1 h; default 5 min);
- launch at login;
- alert thresholds: orange (1–50% left; default 20%) and red (0–49% left;
  default 10%, always below orange);
- hiding harnesses from the panel and the icon.

The same options live in `UserDefaults`, so they can be set from the terminal
too:

```bash
# Refresh interval in seconds (default 300, minimum 60)
defaults write com.belizariogr.agentwatcher refreshInterval -int 600
# Fraction left at which the icon turns orange (default 0.2)
defaults write com.belizariogr.agentwatcher alertThreshold -float 0.25
# Fraction left at which the icon turns red (default 0.1; must be below orange)
defaults write com.belizariogr.agentwatcher criticalThreshold -float 0.1
# Hidden harnesses (ids: claude, codex, cursor)
defaults write com.belizariogr.agentwatcher hiddenProviders -array codex
```

## Debugging

```bash
swift build
.build/debug/AgentWatcher --dump              # prints the limits and exits
.build/debug/AgentWatcher --snapshot /tmp/aw  # renders the panel and icon to PNG
```

## Adding a harness

Implement `UsageProvider` in `Sources/AgentWatcherCore/Providers/`
(`isInstalled()` + `fetch()` returning `ProviderUsage`) and register it in
`UsageStore.allProviders`. An optional logo goes in
`Sources/AgentWatcher/Logos.swift`.
